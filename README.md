# ECLIPSE 星蚀 3.0

**让 AI 看懂聊天氛围，再决定要不要切换说话风格。**

适用于 AstrBot 的情境感知插件：减少关键词误触发，在真正合适的场景临时切换风格；也能在轻松的聊天中，偶尔给 AI 一点自然表达亲近的灵感。

**不绑定任何角色名字，不修改原人格，不要求搭配记忆插件。**

</div>

> **版本状态：** 3.0.0 · 社区版 · 已做离线检查，仍建议在自己的 AstrBot 中验证。  
> **适配范围：** 插件元数据声明 AstrBot `>=4.24.0,<5`，主要面向 4.x；不同插件组合仍可能存在兼容差异。  
> **特别提示：** 3.0.0 的省钱预筛选有漏判短句、连续上下文的已知问题，见下文「最重要的设置：`candidate_only`」。这不是已经修复的 3.0.1。

## ✨ 它能做什么？

你可能遇到过：只是随口提到某个成人话题，AI 就突然切换成特别大胆的语气；真正进入相应的连续聊天场景时，它却没反应。

星蚀尝试把**“提到了什么词”**和**“现在到底在做什么”**分开判断。

| 功能 | 通俗解释 |
| --- | --- |
| 三阶段场景判断 | **普通 → 候选 → 已确认**。候选阶段只是观察，不会马上切换风格。 |
| 临时切换风格 | 只有确认正在持续的特殊亲密聊天场景时，才给本轮模型请求增加专用语气提示。 |
| 自然退出 | 场景结束后停止强风格注入；不会强制清除普通的撒娇、温柔或聊天余温。 |
| 低频主动亲近 | 可选：在上下文允许时，偶尔建议 AI 主动表达想牵手、拥抱、贴贴、亲吻或想念。 |
| 进一步亲密邀请 | 可选且默认关闭；需要足够明确的双向亲近氛围，并经过独立语境判断。**邀请不会自动切换特殊模式。** |
| 控制频率 | 主动亲近有概率、轮数、冷却时间和每日上限，不会每隔几句机械触发。 |
| 状态与诊断 | 在私聊发送命令即可查看当前模式、最近判断、分类调用和注入次数。 |

**它不做什么：** 不会自己定时给别人发 QQ 消息，不负责长期记忆，不会修改其他插件数据库，也不会替你重写原本的人格提示词。模型最终回复仍取决于模型能力、当前上下文和其他插件。

## 🚀 三分钟上手

### 第 1 步：安装

**方式 A：AstrBot 插件管理界面**

1. 下载社区版压缩包 `ECLIPSE_3.0_Community.zip`。
2. 在 AstrBot WebUI 的「插件管理」中，选择 ZIP 安装/上传入口并安装。
3. 按界面提示重载插件，必要时重启 AstrBot。

**方式 B：手动安装**

将 ZIP 解压，把其中的 `astrbot_plugin_eclipse` 文件夹放到 AstrBot 的 `data/plugins/` 下。确保 `main.py`、`metadata.yaml`、`_conf_schema.json` 位于这个文件夹的第一级，不要套两层同名文件夹。然后重启 AstrBot。

### 第 2 步：设置允许使用的账号（必做）

打开 **AstrBot → 插件管理 → ECLIPSE 星蚀 3.0 → 配置**。

找到 `allowed_user_ids`：填写**允许使用本插件的消息发送者 ID**（例如你自己的 QQ 用户 ID），一个 ID 一项。**不要填机器人的 QQ 号。**

社区版默认列表为空，意味着**所有人都不会启用**。这是为了防止刚安装就影响所有人的聊天。插件只对授权的**私聊**生效，不在群聊启用。

### 第 3 步：先用一套稳妥设置

| 配置项 | 初次使用建议 | 作用 |
| --- | --- | --- |
| `enabled` | 开 | 插件总开关 |
| `semantic_detection` | 开 | 允许用模型判断场景 |
| `candidate_only` | **准确度优先：关** | 避免漏掉没有命中特定词语的连续聊天；会增加 API 调用 |
| `entry_confirm_turns` | `2` | 默认连续两次确认，才进入特殊模式 |
| `classifier_provider_id` | 留空 | 使用当前会话的模型；也可以填已有的低成本模型提供商 ID |
| `affection_enabled` | 先关 | 先测场景切换，稳定后再启用低频主动亲近 |

保存后，在**白名单账号与 AI 的私聊**中发送：

```text
/星蚀 状态
/星蚀 诊断
```

如果能看到 `ECLIPSE 星蚀 3.0`、模式以及判定计数，就表示命令已正常响应。

### 第 4 步：正常聊天测试

不要只拿单个关键词测试。可以分别试试：

- 正常生活聊天、洗澡时随口聊到成人话题：**不应仅因提到词汇就切换**。
- 讨论过去的经历或未来的打算：**通常保持普通模式**。
- 双方明确进入并持续同一个当前亲密场景：**可能先进入候选，再在连续确认后切换**。
- 改聊作业、技术问题，或明确停止：**应退出特殊场景**。

如果发现漏判，先看下面的已知问题；不要急着往关键词列表里硬塞词。

## ⚠️ 最重要的设置：`candidate_only`（3.0.0 已知限制）

这是目前最容易让人困惑的一项。

| 设置 | 优点 | 代价 |
| --- | --- | --- |
| `true`（3.0.0 默认） | 明显无关的消息可以不调用语义模型，更省 Token | **目前只根据最新一句话做本地初筛**，连续互动中的短句、含蓄表达可能被直接跳过 |
| `false`（准确度优先推荐） | 让模型有机会结合近几轮聊天判断，不容易被初筛直接拦截 | 多数普通消息也可能增加一次模型分类调用，增加费用和延迟 |

**典型症状：** 明明已经有连续的亲密上下文，发送 `/星蚀 诊断` 却长期看到：

```text
语义阶段：普通
最近判定：无相关情境：不花模型费用
场景分类调用：一直没有增加
```

**临时解决：** 在 WebUI 将 `candidate_only` 关闭，保持 `semantic_detection` 开启、`entry_confirm_turns=2`；保存后继续测试。若分类次数增长但不进入场景，再查看模型的判定结果。

**注意：** 本 README 只是说明当前 3.0.0 的规避办法，**并未修改插件的默认配置或修复代码**；后续的上下文感知初筛需要另行发布代码更新。

## 💬 聊天命令

以下命令在**已授权的私聊**中使用。

| 命令 | 效果 |
| --- | --- |
| `/星蚀 状态` | 查看模式、语义阶段、最近判定和累计注入次数 |
| `/星蚀 诊断` | 查看场景分类次数/失败、亲近语境判断次数、提示加载状态等 |
| `/星蚀 自动` | 恢复由模型自动判断场景 |
| `/星蚀 开启` | **手动强制开启**当前私聊的特殊风格，不依赖语义判断，直到切换模式 |
| `/星蚀 退出` | 结束特殊状态并回到自动判断；不强制抹去正常语气余温 |
| `/星蚀 关闭` | 对当前私聊关闭特殊风格和随机亲近建议 |
| `/星蚀 样例` | 查看自定义参考句子的读取行数，不显示具体文本 |

也支持英文命令前缀 `/eclipse`。手动开启是人为强制切换，与“自动模式有没有识别成功”是两回事。

## 🫶 让 AI 偶尔主动亲近

如果你喜欢 AI 偶尔在**已经轻松亲近的聊天氛围**里主动说想抱抱、想亲亲，可以在 WebUI 开启 `affection_enabled`。社区版**默认关闭**。

工作方式并不是每几轮强行插入一句话，而是：

1. **先过滤不适合打断的场合**：例如学习、工作、求助、争执、难过、明确拒绝等。
2. 满足最少聊天轮数、冷却时间和每日限额后，按低概率抽取一次检查机会。
3. 模型分析最近的文字上下文；只有认为气氛合适，才给 AI 一个**可忽略的亲近灵感**。
4. AI 自己组织回复；如果不自然，可以不采纳。这只是提示注入，不是实际发出邀请的成功回执。

建议起步参数：

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `affection_enabled` | 关 | 是否启用聊天中的主动亲近 |
| `affection_chance_percent` | `8` | 抽中**额外语境检查**的概率，不是实际邀请概率 |
| `affection_min_turns` | `6` | 两次亲近灵感之间至少间隔6轮用户消息 |
| `affection_cooldown_minutes` | `180` | 至少相隔3小时 |
| `affection_daily_limit` | `2` | 每个私聊每天最多注入2次灵感 |
| `allow_romantic_invites` | 关 | 是否允许更进一步的亲密邀请方向 |
| `romantic_share_percent` | `5` | 当上下文已被判定允许进一步亲近时，再低概率选择该方向 |
| `reply_segment_hint_limit` | `3` | 建议回复尽量不超过3条，**不是强制消息限流** |

**特别说明：** 主动亲近功能只影响你发来消息后 AI 的**这一轮回复**。如果你希望 AI 在你没有发消息时自己来联系你，需要搭配 AstrBot 的主动消息/定时触发机制；星蚀本身不负责主动发送。

## ⚙️ 其他 WebUI 选项说明

| 选项 | 解释与建议 |
| --- | --- |
| `classification_timeout_seconds` | 语义分类模型的等待上限，默认12秒；超时或报错时按普通场景处理 |
| `scene_timeout_seconds` | 已确认场景的连续性有效期，默认300秒；**不是强制保持特殊风格300秒**，每轮仍会判断 |
| `candidate_timeout_seconds` | 候选场景等待再次确认的有效期，默认180秒；候选阶段不注入特殊风格 |
| `inject_system_anchor` | 已确认特殊场景时，把专用风格追加到本轮系统提示，默认开 |
| `inject_runtime_every_turn` | 已确认特殊场景时，注入每轮临时提示，默认开 |
| `system_prompt_override` | 在网页直接填写特殊场景风格；留空时读取 `prompts/亲密场景风格.txt` |
| `runtime_prompt_override` | 在网页直接填写每轮临时提示；留空时读取 `prompts/每轮临时提示.txt` |
| `inject_reference_examples` | 是否读取 `prompts/参考句子_自行填写.txt`，社区版默认关，以防台词复读 |
| `max_reference_chars` | 参考句子最多读取多少字符，避免过度占用 Token |
| `max_runtime_chars` | 临时提示最多读取多少字符 |
| `debug_log` | 只记录运行状态、计数和错误类型的日志开关，默认关 |

普通使用通常不需要修改这些高级设置。**不要把 API Key 填到 `classifier_provider_id`**，这里要求的是 AstrBot 中已有的模型提供商 ID。

## 🎭 自定义 AI 风格

插件文件夹内提供三个通用文本文件：

```text
astrbot_plugin_eclipse/
├── main.py
├── metadata.yaml
├── _conf_schema.json
├── settings.json
├── README.md
├── logo.png
└── prompts/
    ├── 亲密场景风格.txt
    ├── 每轮临时提示.txt
    └── 参考句子_自行填写.txt
```

- `亲密场景风格.txt`：已确认特殊场景时的整体说话方式。
- `每轮临时提示.txt`：每次已确认场景请求时的短提示。
- `参考句子_自行填写.txt`：你自己编写的句子；默认**不注入**，需要手动开启 `inject_reference_examples`。

你也可以在 WebUI 中直接填写 `system_prompt_override` 和 `runtime_prompt_override`，覆盖相应 TXT 的读取结果。

**建议：** 提示文本尽量短，描述“何时使用、什么语气、何时结束”，不要堆几百句固定台词，更不要复制别人带有私人信息的提示词。升级之前请备份自己改过的 `prompts` 和配置。

## ❓ 常见问题

<details>
<summary>装完了没反应，怎么办？</summary>

先确认插件已加载、自己是在**私聊**、已将**发送者用户 ID**写入 `allowed_user_ids`。然后发 `/星蚀 状态`。社区版默认白名单为空，属于正常安全策略。
</details>

<details>
<summary>正在聊亲密话题，却始终显示「普通 / 无相关情境」？</summary>

这是 3.0.0 的已知漏判情况。先将 `candidate_only=false`，再用 `/星蚀 诊断` 查看模型分类调用是否增长。注意这会增加费用。
</details>

<details>
<summary>只是开玩笑或讨论成人话题，会触发吗？</summary>

自动模式的目标是**不触发**。关键词只应帮助决定是否进一步判断，而不是直接开启；但模型可能误判。需要绝对保持普通时，可手动用 `/星蚀 关闭`。
</details>

<details>
<summary>模型判定调用增加，但仍不进入特殊模式？</summary>

默认需要连续两次明确确认（`entry_confirm_turns=2`），而且分类结果不确定时会回到普通。如果分类失败，检查 AstrBot 模型提供商是否可用、超时是否过短及诊断里的失败计数。
</details>

<details>
<summary>为什么退出后还有 ❤️ 或撒娇？</summary>

退出只停止**插件的强风格注入**，不应把角色原本的温柔、普通亲近或当前聊天余温强制抹掉。旧对话上下文以及原本的人格提示词也会影响 AI 的语气。
</details>

<details>
<summary>为什么没有主动提出抱抱？</summary>

确认开启 `affection_enabled`。它还受低概率抽样、最少轮数、冷却、每日上限和模型上下文审核影响；即使注入了灵感，模型也可以选择不提。
</details>

<details>
<summary>启用星蚀后，我不发消息 AI 会主动来找我吗？</summary>

不会。要实现无人发言时主动私聊，需要单独的主动消息/定时调度插件。注意避免两个不同插件重复实现同一触发器。
</details>

<details>
<summary>我的聊天内容会被发到哪里？</summary>

语义判断会把最近若干轮**文字上下文的节选**发送给你选择的模型提供商。如果使用第三方云模型，就会受到该服务商的数据处理政策约束。星蚀没有额外的独立上传服务，也不负责长期存储聊天原文；插件自身会保存必要的会话状态与统计。请勿将个人密钥或私密资料写进公开仓库。
</details>

<details>
<summary>和主动消息、长期记忆、其他人格插件冲突吗？</summary>

功能分工不同，可以搭配使用；但如果其他插件也会在相同请求中注入强制风格、控制消息分段或手动切换模式，效果可能互相影响。建议一次只启用一套相同用途的风格切换插件。
</details>

## 🔒 隐私、成本与已知限制

- **隐私：** 社区版没有预置任何用户 QQ 号、私人对话、私人提示词或 API 密钥。请自行填写白名单与模型提供商 ID。
- **成本：** 自动场景判断可能产生额外模型请求；`candidate_only=false` 可改善漏判，但费用可能明显上升。低频主动亲近在抽中之后还可能额外调用语义模型。
- **模型差异：** 不同模型的分类能力、文字风格与平台限制不同，无法保证100%准确或完全照做。
- **不做持久化人格修改：** 只对符合条件的当前模型请求附加提示，不修改主角色配置和其他记忆插件。
- **已知限制（3.0.0）：** `candidate_only=true` 时仅检查最新一句话能否通过候选初筛，可能忽略前文语境。关闭它是当前版本的规避办法，**不等于代码已修复**。
- **测试状态：** 已进行离线结构和逻辑测试；建议先用测试账号在实际 AstrBot 环境验证，再大范围部署。
